# What binnacle can reach

binnacle runs inside Claude Code as your user. Mods are not sandboxed, so this file lists everything it uses.

| Capability | Used for |
|---|---|
| `session.usage`, `session.model`, `session.cwd`, `env.get('HOME')` | status line figures; `HOME` also locates binnacle's data directory `~/.claude/plugins/data/binnacle-binnacle/` and transcripts under `~/.claude/projects/` (compaction count, Search), and shortens paths in the Session lists; the guard also uses `HOME` to resolve `~` and to treat a session started in `$HOME` as having no safe zone |
| `settings.read` (user source) | one-time hint when a `statusLine` setting exists |
| `ui.*` | drawing the status line, panel, badge and toasts; asking via the built-in dialog |
| `state`, `store` | session values, your panel settings, and the index of the activity history in `~/.claude/plugins/store/binnacle_*.json` (plain JSON): one row per saved session with its id, start and end times, directory, the first 120 characters of its first prompt (masked) and its size. It also keeps one flag recording that the `statusLine` hint was shown. Before 0.4.0 the saved sessions themselves were kept here too; each is moved to its file (next row) once, in the background just after a session starts, and deleted from the store; one that fails to move stays and is read from there, and the move is tried again at the next start |
| `fs.read`, `fs.write`, `fs.list`, `fs.exists`, `process.run` (`rm -f`) | the activity history, one file per saved session in binnacle's own data directory, `~/.claude/plugins/data/binnacle-binnacle/sessions/<session id>.json` (plain JSON): the first 120 characters of each prompt and whether Claude Code started that turn itself (read from the prompt's origin), agent tasks and the first lines of their reports, permission and guard decisions, command summaries, file names with line counts. It also keeps the session's compactions (trigger, tokens, duration). Likely secrets are masked before saving, on a best-effort basis (see **Masking** below). Diff bodies are never saved. A session with no turn is not saved; one record is kept under 3 MiB (UTF-8, below the 4 MiB file limit) by dropping its oldest one-off events. Saved sessions started more than 90 days ago are deleted, and past 500 sessions or 100 MiB in all the oldest go first; the current session is never dropped. `/binnacle activity clear` deletes all of them but the current session, after asking; under `claude -p`, with no one to ask, it deletes nothing. `$.fs` has no delete, so a session file is deleted by running `rm -f <that one file's absolute path>` as an argument list (no shell, never `-r`, 10-second timeout), and only for a session id made of letters, digits, `_` and `-`; any other id never becomes a path |
| `session.id` | keying the saved activity to the session, so `--resume`, `--continue` and `/resume` inside Claude Code carry on its record and `/clear` or `--fork-session` starts a new one; read on every draw of the status line and the panel, to notice a `/clear` or `/resume` |
| `clock` | waiting 300 ms after you stop typing in Search, starting the compaction reads just after the hook that asks for them (`after(0)`), moving saved sessions out of the store just after a session starts (`after(0)`), redrawing durations every 15 seconds, the panel's Agents tab once a second while it is the tab drawn and an agent on it runs, waits or has just finished, and once right after a draw that finds `/clear` or `/resume` started binnacle's session values over (`after(0)`), to load them back |
| `command.register` | `/binnacle` |
| `process.run` | read-only commands with a 10-second timeout. To preview an “ask” before you answer: `find`, `git clean -n` (with the command's own flags, only when every flag is a known one, so `-n` keeps it a dry run; `--no-dry-run` or `-i` is never previewed), `git log`, `git status`, `kubectl get`, and for `rm` `bash -c <fixed listing script>` with the targets as arguments (the script only runs `find … -type f` on them); paths with `$` or backticks are never previewed. For the Diff tab's Workspace view, git runs as a fixed argument list without a shell, in the session directory, only when you run `/binnacle diff`, open the Diff tab, choose Workspace or press Refresh: `git --no-optional-locks -c core.quotepath=false diff-index -p -M --no-color --no-ext-diff --no-textconv --src-prefix=a/ --dst-prefix=b/ HEAD` and `git --no-optional-locks -c core.quotepath=false status --porcelain`. Neither writes `.git/index` |
| `process.run` (transcript) | `grep -F '"subtype":"compact_boundary"' <transcript>` and `grep -oE '"session_id":"[0-9a-f-]{36}"' <transcript>` for the compaction count, at session start, after a compaction, at the end of every turn (Claude Code 2.1.300 reports no `/compact`), after `/clear` or `/resume`, and when you turn on *count compactions across forks* (the second only reads the back-links a fork copies in; with *count compactions across forks* on, both also run on up to nine earlier sessions' transcripts); `grep -oE '"permissionDecision":\{[^}]*\}' <transcript>` for Permissions → *Who decided* and to tell auto mode (the latest settled ask), when the tab opens and at the end of every turn (only the small decision objects are printed: who decided and how, never the command or its output); `perl -e '<read one block>' -- <transcript> <offset> <length>` for Search, in reads of 3 MiB: perl opens the file read-only, seeks, reads one block and prints it, and writes nothing. Search reads the transcript (of one over 24 MiB, the newest 24 MiB) and keeps in memory the newest 20,000 entries, each cut to 2,000 characters. Paths and numbers are arguments, never shell text |
| `fs.stat`, `fs.list`, `fs.exists` | finding this (or a saved) session's transcript under `~/.claude/projects/`, its size and modification time; read-only there |
| `config.list`, `command.run` (`model`, `effort`) | the model and the effort on the status line, only when you click one: it runs `/model` or `/effort` with no argument, which opens Claude Code's own picker; there **Enter saves the pick as your default** for new sessions in `~/.claude/settings.json`, `s` keeps it to this session, Esc changes nothing. `config.list` only reads whether the model row is locked |

**Transcript.** For Search, binnacle reads the whole transcript of the session you search (your prompts, the replies, every tool's input and output — which can hold secrets). It reads whole transcripts only when you use the Search tab; the compaction count reads only the `compact_boundary` rows and the session ids grep prints (of the earlier sessions' transcripts too, while counting compactions across forks is on). It reads the file by running `perl` read-only (open, seek, read, print), never through a shell. What it reads stays in this process's memory (at most two sessions' indexes): it is masked (best effort, the same rules as Activity) before it is indexed or shown, never written to the plugin store or any file, and never sent anywhere. binnacle still keeps no copy of the conversation.

**Masking.** Saved Activity text and Search text go through one best-effort text filter, not a secret scanner. It replaces with `***`: PEM blocks; `Bearer` tokens; AWS access key ids (`AKIA…`); the path of a Slack incoming webhook; tokens with a known prefix (GitHub `ghp_` / `github_pat_`, GitLab `glpat-`, Slack `xox…-`, Stripe `sk_` / `pk_` / `rk_` `live` / `test`, Google `AIza`, npm `npm_`, `sk-` / `sk-ant-` / `sk-proj-`); secret URL query parameters (`key`, `sig`, `signature`, `auth`, `code`, `access_token`, `refresh_token`, `id_token`, `client_secret`, `apikey`, `X-Amz-Signature`, `X-Amz-Credential`, `X-Goog-Signature`); the value after a key named like `token`, `secret`, `password`, `passwd`, `api_key`, `access_key`, `private_key`, `credential(s)` or `authorization` (`=` or `:`, quoted or not); `--password` values; `user:pass@` in URLs; and runs of 32 or more characters that mix letters and digits (not a 40-character git SHA), checked piece by piece inside a run that reads as a path. Some secrets still get through: short tokens with no known prefix and no key name; a secret split by `/` whose pieces look like words or are under 32 characters; a keyed value that contains a blank, a quote, a comma, or an `&` followed by `name=` (only the part before it is masked); and long values made only of letters or only of digits.

binnacle makes no network requests and writes no files of yours: the only files it writes or deletes are its own saved sessions under `~/.claude/plugins/data/binnacle-binnacle/` (a click on the status line's model or effort opens Claude Code's `/model` or `/effort` picker, whose Enter saves your default in `~/.claude/settings.json`). It calls no model. The guard is best effort: commands hidden behind variables, aliases or command substitution inside double quotes are not recognised.

## Plugins

Other plugins add to binnacle's interface through `$.binnacle` and hear back through `binnacle.notify` ([docs/plugins.md](docs/plugins.md)).

- **Data only.** A plugin sends text, colours, ids and rows. binnacle draws text as one line with control characters as visible stand-ins, cuts it to fixed limits, drops colours that are not hex values or plain names, and caps how many buttons, parts, lines, settings, tabs, rows and guard sources each plugin has.
- **Its own things only.** binnacle files every registration under the name Claude Code gives the caller (`next.origin.plugin`, which a plugin cannot set) and refuses changes to another plugin's. The person can turn off everything a plugin added in Settings → Plugins.
- **Who sent a notice.** Any plugin can call `$.binnacle.notify`, and in a real session that call reaches the other plugins' subscriptions. A plugin acts only on a notice whose `next.origin.plugin` is `binnacle` (the template and the plugins in the marketplace do).
- **What binnacle cannot stop.** Any installed plugin can subscribe to `binnacle.<call>` and change what another plugin sends (not who sent it). A plugin is code that runs as you and can read and write files anyway: install plugins from the reviewed marketplace, where every entry is pinned to a commit.
- **Stored for plugins.** The values of plugin settings are kept with binnacle's own settings in `~/.claude/plugins/store/binnacle_*.json`.

Report a security issue by opening a private advisory on the repository.
